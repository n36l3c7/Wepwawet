Changelog

The full history is in CHANGELOG.md. Versions follow Semantic Versioning.

1.0.0 · 2026-11-15

The first stable release.

Added

  • wepwawet benchmark: accuracy on RIPE Atlas anchors, with the error of every stage (passive, pings, traceroutes, final) and the share of anchors inside the stated uncertainty.
  • Every report keeps the estimate after each stage.
  • Rate limits are remembered: after a 429 a source is not called again before the time it asked for, across restarts.
  • Every passive source has a 90-second limit; a slow one is reported and the run goes on.
  • WEPWAWET_TOKEN for a fixed serve token.
  • Methodology page.
  • Operator rule for Init7 router names.

Changed

  • Fusion keeps the centre of a small RTT region (radius up to 50 km) and only names it after the best candidate.

Fixed

  • A misplaced measurement probe no longer makes an address look anycast; it is excluded and reported.
  • A history run written by another version gives a clear message instead of a server error.
  • The explanation counts the origin network's data centres instead of listing them.

0.5.0 · 2026-11-15

One answer, with its reasons, kept and shareable.

Added

  • Evidence fusion: the estimate is the best place inside the RTT region ranked by the agreeing soft evidence; answers outside the region are ruled out and listed; confidence from region size, agreement and network class; plain-language explanation.
  • History of every run, with diff (estimate movement, confidence, network, GeoIP answers, convergence, first changed hop) and re-run.
  • Export: JSON, GeoJSON, KML, Markdown report, CSV of hops, PNG of the map.
  • Bulk mode in the interface and with wepwawet bulk: a shared test budget, a queue, pins coloured by confidence, CSV and GeoJSON summaries.
  • wepwawet locate --format/--output, wepwawet history list|show|diff|export.

0.4.0 · 2026-11-15

Paths: Wepwawet now traces the routes to the address and reads the routers on the way.

Added

  • Traceroutes (Globalping mtr, local mtr or traceroute) from the fastest probes, over TCP when the target drops ICMP.
  • Location hints in router names: operator rules (Arelion, NTT, Cogent, Hurricane Electric, Lumen, GTT, Sparkle, Deutsche Telekom, Google), UN/LOCODE, city names, airport and IATA metro codes; a hint is kept only if the hop's RTT allows it.
  • Exchange points: routers inside a PeeringDB peering LAN are placed at that exchange.
  • Path convergence, access-delay estimate with the likely access technology, and access-corrected multilateration.
  • Path flags: MPLS or hidden hops, falling RTT (asymmetric return), unresponsive tail.
  • Interface: traceroute paths and located routers on the map, convergence point, Hops tab, path summary.
  • Airports (OurAirports) and UN/LOCODE in wepwawet data update.

0.3.0 · 2026-11-15

Measurements: Wepwawet now pings the address and works out where it can be.

Added

  • Measurement sources: Globalping (free, optional token), RIPE Atlas (only with a credit budget), this machine and your servers over SSH.
  • Two-stage ping campaign: a global sweep, then a regional zoom near the fastest probes and the passive answers; TCP fallback when the target drops ICMP; test budget shared with Globalping's hourly limit.
  • Multilateration on an H3 grid: feasible region, centre, uncertainty radius and the GeoNames cities inside it; optional CBG calibration against RIPE Atlas anchors.
  • Anycast detection from speed-of-light violations.
  • Interface: probes coloured by RTT, RTT disks, region, estimate with uncertainty and confidence, layer toggles, Probes tab, budget meter.
  • wepwawet locate --passive, /api/budget, GeoNames in wepwawet data update.

Fixed

  • wepwawet locate --json always writes UTF-8.

0.2.0 · 2026-11-15

Passive evidence: Wepwawet now looks addresses up.

Added

  • Input validation: IPv4, IPv6 and hostnames (every A and AAAA record); special-purpose ranges are refused with the reason.
  • Sources: local GeoIP databases, RIPE IPmap, RIPEstat, RDAP, reverse DNS with a /24 neighbour sweep, PeeringDB, Shodan InternetDB, Shodan and Censys.
  • Network classification (residential, mobile, hosting, CDN, VPN, education) with caveats shown in the interface.
  • wepwawet locate, wepwawet providers, wepwawet data update|status.
  • Interface: Run and Stop, live progress, Summary, Evidence and Raw tabs, GeoIP answers with accuracy circles, located answers and PeeringDB facilities on the map.
  • API keys from environment variables or a private secrets.toml.
